# PROGRESS.md で次の作業をすぐ出す

/clear 後に遅くなる原因は、読む量ではなく「次は何か」を毎回組み立て直すこと。順番を先にファイルへ書いておき、聞かれたら1番を出すだけにする。

## 「次の作業」と聞かれたら
1. 冒頭の「▶ 次にやること」だけ読む（全文は読まない）:
   `awk '/^## ▶/{f=1;print;next} f&&/^## /{exit} f' PROGRESS.md`
2. `git log --oneline -3` で、書き換え忘れ（終わったのに残っている項目）が無いか見る
3. 1番を結論1〜2行で出す。【途中】なら「次の一手」から。順番を組み直さない
4. 1番がボス待ち（実機確認など）なら、それを一言添えて次の番号を出す

## 書き換えるとき
- 作業を始めた／1つ終わった／ボスに質問して止まった／方針が変わった時だけ。返事のたびには書かない
- 変わる行だけ直す。同じセッションで読み直さない
- 終わった項目は「完了した機能」へ移す。順番に迷うものはボスに聞いてから並べる
- commit・push は機能が1つ終わった時と、セッションを閉じる前だけ

## 冒頭の形（この順で）
```markdown
## ▶ 次にやること（上から順に。1番から手を付ける）
1. 【途中】〇〇。どこまで: △△。次の一手: □□
2. 【未着手】〇〇

### ボスが手でやること
### 未確認のまま（必要になったら確かめる）
### 保留（理由つき）
```
その下に「完了した機能」「決めたルール・やめた方法（理由つき）」を置く。

## PROGRESS.md が無いフォルダ
- 上の形で作る。HANDOVER.md・NOTES.md など引き継ぎに当たるものがあれば、中身を移す
- 古いファイルを消すか残すかはボスに聞く
- そのフォルダの CLAUDE.md に進捗ルールが重ねて書いてあれば、「progress スキルに従う」の1行に縮めてよいかボスに聞く
